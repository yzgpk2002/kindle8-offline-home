# KUAL 直达主页与解除联网前置限制

## 两个独立限制

1. **VoiceView 占用时不允许打开浏览器**：先验证关闭 VoiceView 后仍可由本机音频服务播放，最终把耳麦录放下沉到独立 HFP 服务。
2. **原浏览器在无无线连接时拦截页面打开**：即使 localhost 服务正常，原浏览器仍提示开启无线。它属于应用入口的联网检查，不能靠本机 HTTP 返回 200 来证明问题解决。

因此“解决联网限制”的准确成果是：**本机主页不再要求 Wi-Fi 或 USB 在线**。联网网站、DeepSeek API 等仍需要真实互联网连接。

## 失败方案与最终方案

曾尝试独立页面引擎副本和应用注册；发生 Application Error 和恢复困难，没有把这一路线推广为正式方案，也没有把页面引擎改成 root 运行。

最终仍使用原厂 `/usr/bin/mesquite`，通过本地应用加载：

```text
file:///mnt/us/kt3-home/offline-home/
         ↓ 页面 XHR
http://127.0.0.1:8083/
```

页面由 framework 用户运行，准备脚本从已有本机服务取得 POST token 后注入模板。本机 Host、回环校验和 token 校验保留；未扩大成任意跨域开放接口。

## 离线验收不能只看 Wi-Fi 图标

最初只将 `wifid.enable` 设为 0，连接管理器随后重新打开无线，造成“看起来离线”的误判。另一次旧测试观察器到时恢复 Wi-Fi，用户指出测试时 Wi-Fi 已开启，原结论被撤回。

最终同时记录无线总开关、Wi-Fi 开关及 USB carrier。用户拔线后从书库重新点 KUAL，完成录音、保存、回放并打开书；设备日志覆盖同一时间段，确认两个无线开关均为 0、USB down，并记录音频和阅读器活动。这才记为离线验收通过。

## KUAL 直达与权限

对核对过的 KUAL 工件，只在私有启动路径中增加可回退的固定入口；原菜单保留。目标 Java class 版本保持 48，变换后做字节码结构检查。不发布修改后的 JAR，也不假设任意版本均能打同一补丁。

- 点击书库 KUAL → 手动入口 → 本地主页。
- `/mnt/us/kt3-home/USE_KUAL_MENU` 存在时回原菜单；启动失败同样提供回退路径。
- 提权只通过固定动作辅助程序；页面保持普通 framework 身份。
- 更新 JAR 时保留旧 inode 的备份链接，避免 CVM 缓存已删除 ZipFile 导致根分区无法重新只读。该问题不是普通 HTML 刷新能解决的。

## 入口提速和页面生命周期

原入口每次固定等待两秒，还加载 Python 仅用于 HTTP 探测。优化为系统 curl、精确 `KT3_OK` 探测和有界 250 ms 重试；已运行服务的热访问直接复用。

现场一次基线约 9.83 秒，两次优化约 4.21 和 4.14 秒，测量终点是页面 JS beacon，不是首像素或手指响应。用户确认明显更快。没有将它写成冷启动四秒的保证。

页面在 `ongo` 时保存应用上下文、立即更新状态，在后台暂停轮询；自动连接时较快轮询，避免旧的长轮询周期造成按钮状态迟滞。这些修正与触摸误判问题分开记录。

## 现有桌面

标题左右为书库与退出；第一块双月日历及日期备忘；第二块长条录音机、录音列表、设置；下方是 QQ 音乐入口/本地文件和 DeepSeek 文本。

QQ 官网能渲染但实测点歌无响应。DeepSeek 官网现场白屏，另一次命令行请求返回 429；两项观察不能证明永久不兼容，也不能算文本对话已成功。当前选择轻量 API 文本界面，Key 留空，不调用远端。
