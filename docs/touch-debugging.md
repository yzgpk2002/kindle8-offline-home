# 触摸失效：三个不同层次的问题

## 1. 拆掉外框后的失效：有明确实物对照

最初触摸是在拆掉前框后失效，原装黑色前框/红外导光结构未装回。用户装回外框后立即反馈触摸恢复。这是本次最明确的机械条件关联：KT3 的触摸工作需要完整、正确对位的红外光路，不能只看显示画面正常就判断触摸硬件条件满足。

排查顺序应先检查外框是否完整安装、边缘是否被线材遮挡、导光区域是否有灰尘或松动。不要先刷固件、换排线或断言触摸控制芯片损坏。

## 2. 后期卡死：不能全部归到外框

新主页实验中出现 Application Error、重启后点不动、退出后约十秒才恢复等现象。排查把链路拆成：

```text
红外触摸 → Linux input events → Xorg 多点识别/焦点 → 页面事件 → HTTP 命令 → 音频工作进程
```

- 先恢复原书库并停用新主页自启，确认是否在原系统同样失效。
- 只读采集 `/dev/input/event0`，同步检查窗口焦点和页面事件；不独占输入设备。
- 单个短窗口的零事件不证明整个时段驱动坏了；被遮挡的 xev 窗口也不能证明界面没有收到输入。
- 曾读取 `zforce2 ledlevel` 后紧接着出现 start-frame 和 I/O 错误，正常扫描模式切换没有恢复；一次不再访问该诊断节点的干净重启后恢复。记录为时序相关证据，不能推导为所有故障的唯一根因。

不要重复读取那个曾扰动扫描的 sysfs 诊断节点来“确认故障”。当前版本没有修改触摸驱动，也没有把忽略第二触点当作修复。

## 3. 重连后“录音按钮十秒无响应”

后端测试在已连接状态约 27 ms 确认录音；一次重连后的自动请求约 131 ms 确认。用户仍报告手点无反应，而同期没有对应页面 pointer/record 请求。因此不能把这些后端数值写成触摸体验已经修复。

后续对照中，一次清晰单指按下/抬起成功切换到备忘；随后触摸被报告为两个槽位和双指手势，语音页没有切换。证据支持**该轮**问题发生在触摸/手势到页面事件之前。用户随后暂缓该问题排查。

与此同时，页面增加了前台 `saveContext` 确认、返回即刷新和后台暂停轮询；它们修正生命周期问题，但尚不足以证明全部历史十秒延迟消失。

## 结论如何写

| 说法 | 是否成立 |
|---|---|
| 拆外框导致的首轮失效，装回后恢复 | 有实物前后对照 |
| 后端命令可以快速进入录音 | 有程序测量，但不是端到端触摸延迟 |
| 所有触摸问题都是 CPU 太慢 | 无证据 |
| 所有问题都由前框造成 | 无证据 |
| 最终设备能触摸、返回书库和看书 | 用户多轮确认 |
| 间歇误触已彻底根治 | 未验证，保留为已知限制 |
