# 验收与证据边界

日期：2026-10-25。设备测试、用户听感与模拟测试分别列出，不能互相替代。

## 已取得的证据

| 项目 | 证据 | 结论 |
|---|---|---|
| 首次拆机触摸失效 | 拆框后失效、装回后恢复的用户对照 | 前框/红外光路条件重要 |
| USB root | RAM uid=0，随后原系统正常重启仍能公钥 SSH | 自定义持久化通过；不保证 OTA 保活 |
| 耳麦输入 | WAV 文件与用户确认清晰人声 | 麦克风输入通过 |
| 持续双工 | 同一会话连续录放，用户听到新录音且无重连 | 不是每段切换控制器 |
| 耳机入盒取出 | 同进程、一次控制器初始化、多次 SCO 建链，无正常断线原生恢复 | 持有服务并重连通过 |
| 原生查询兼容 | 双工期间约 28～34 ms 查询，退出后约 30 ms | 修复已观察的同步查询阻塞 |
| 离线 | Wi-Fi 两开关为 0、USB down 与实际录放/阅读同时记录 | 完全脱离电脑的本地功能通过 |
| KUAL 入口 | 用户直达、回阅读正常；热入口约 4.2 秒 | 直达与热启动改善通过 |
| 屏保唤醒 | 用户确认进入屏保后唤醒，录放阅读正常 | 不延伸为深度挂起结论 |
| 文本模块 | 模拟请求及设备无 Key 拒绝发送检查 | 接口就绪，真实回答待 Key |
| QQ 音乐 | 首页可见，用户点击歌曲无反应 | 在线播放未通过 |

## 自动化检查

公开快照包含 60 项 Python 测试及 Node 页面检查，覆盖会话恢复、过期进程身份、断线/取消、缓存、媒体路径、日期备忘、缺密钥不联网、清空后迟到回答和页面暂停/恢复。测试运行方式见 README；最新运行输出保存在 [测试日志](../logs/publication-tests.txt)。

这些测试不包含真实蓝牙硬件、付费 API 或联网音乐网站，不应当作所有设备兼容性的保证。

## 本次公开文档的核查方法

原始工作目录含早期“未完成”、后期“已修复”记录，按事件顺序重新整理，避免把历史未完成状态或一次成功当作最终全局结论。公开日志删除设备身份、服务器信息、录音内容和密钥，只保留诊断逻辑与必要统计。
